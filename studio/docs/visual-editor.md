# Визуальный редактор Studio: контракт

Документ фиксирует устройство визуального редактора ролика, очередность этапов и проверяемые критерии.
Пользовательское описание возможностей - `studio/README.md`. Правила роликов - `AGENTS.md`, `DESIGN-SYSTEM.md`.

## 1. Основа: источник, идентификация, протокол

**Источник правды - текст `v.html`.** Второй JSON-копии сцены нет. Черновик редактора - полный текст файла
(`draft`) и версия с диска, от которой он начат (`base`).

- Разбор - `src/editor/source.ts`: терпимый токенизатор HTML с позициями в исходнике. Учитывает комментарии,
  `<script>`, `<style>`, `<textarea>`, кавычки атрибутов, void-элементы и незакрытые теги. Ничего не нормализует.
- **Идентификатор объекта** - путь в исходнике `s<номер сцены>` + индексы дочерних элементов: `s2.1.0`.
  Путь вычисляется заново после каждой правки; операция правки возвращает путь объекта после нее
  (вставка, удаление). Пути выбора, блокировки, скрытия и непримененой правки исходника переносятся при любой смене
  текста (правка, undo/redo, версия с диска) - `src/editor/remap.ts`: объект до/после измененного диапазона сдвигается,
  объект с правкой внутри остается. Путь переносится, только если оба крайних положения диапазона (вставка/удаление
  повтора соседнего текста) дают один объект; иначе - только по точному HTML, единственному до и после. Два прежних
  объекта никогда не получают один новый. Остальное снимается (тост для скрытия/блокировки), а не переходит на соседа
  или близнеца (одинаковый HTML): при удалении или вставке одного из близнецов состояние обоих сбрасывается.
- **Патчи - локальные замены диапазонов текста** (`splice`): атрибут, класс, свойство `style`, текстовый фрагмент,
  вставка и удаление элемента. Остальные символы файла не меняются (байт в байт), включая
  произвольный HTML, скрипты, пользовательские атрибуты, отступы и комментарии.
- **Сериализации runtime DOM нет.** Превью только читается: элементы, созданные движком (split-type, `w8`, `wall-bg`,
  концовка), в исходник не попадают.
- **Связь превью и исходника.** Для превью черновик размечается копией с атрибутом `data-studio-id="путь"` у каждого
  элемента внутри `<section>` (`annotate()`), эта копия не сохраняется. Элементы движка без атрибута относятся к ближайшему
  размеченному предку.
- **Протокол превью - редактор** (`src/editor/bridge.ts`): iframe с того же origin, редактор вызывает
  `render(t)` и читает DOM напрямую. Операции: `hitTest(x, y)` (свой геометрический поиск, работает и для
  `pointer-events:none`), `rect(id)`, `visibleIds()`, `scan(times)`, `state(t)` для проверки детерминизма,
  `editorHide(ids)` (только стили превью).
- **Черновик в превью** - `POST /api/videos/:id/draft` хранит размеченный текст в памяти сервера,
  iframe открывает `/video/<id>/__studio-draft.html` (тот же каталог, поэтому `<base href="../../engine/">` и пути ролика работают).
  Два iframe: новый грузится скрыто и показывается после готовности, время кадра сохраняется.
- **Каталог возможностей** - `src/editor/capabilities.ts`: тип объекта (сцена, заголовок, текст, число, карточка, код,
  изображение, аватар, формула, таблица, схема/SVG, 3D, иконка, прочее) и список применимых свойств.
  Нестандартный HTML получает тип «прочее» и правится через исходник.

## 2. Первая поставка: выбор и свойства

- Клик по превью в режиме «Выбор» выделяет объект; рамки наведения и выбора рисуются поверх кадра.
- Дерево объектов сцены с вложенностью; клик выбирает и прокручивает к объекту.
- Блокировка выбора и скрытие - **только состояние редактора** (не в исходнике): скрытый объект получает
  `visibility:hidden` в iframe, сохранение не затрагивает. Индикатор «скрыто в редакторе» виден в дереве.
  При открытии другого ролика история, база, выбор, скрытие и блокировка начинаются с нуля (`store.open`);
  запоздавшие ответы чтения, превью и сохранения для прежнего ролика игнорируются.
- Исходник объекта: непримененый текст хранится в store вместе с путем и HTML объекта на начало правки. Смена выбора,
  вкладки или undo его не теряет и не переносит на другой объект; применение отказывает, если объект изменился или удален
  (текст можно скопировать или отбросить).
- Панель свойств по типу: текстовые фрагменты, ширина/высота, отступы, выравнивание (`text-align`, `align-self`),
  размер/вес/межстрочный/трекинг (только отрицательный), палитра `pal-*`, `.glass`, `.mark`, обводка `ring` у аватара,
  положение у абсолютных элементов.
- **Текстовая правка не теряет разметку**: правятся отдельные текстовые узлы исходника; вложенные `span`, `i.mi`, `.acc`
  остаются. Сущности (`&rarr;`) показываются символами, неизмененный узел не переписывается.
- История `src/editor/history.ts`: undo/redo снимков текста, слияние набора текста по одному полю (800 мс), лимит 200.
- Сохранение: `PUT /api/videos/:id/source` с `base`. На диск уходит снимок черновика; после ответа обновляется только
  база (`store.markSaved`, `src/editor/save.ts`), правки, сделанные во время запроса, и история остаются. Сервер: 409, если файл на диске изменился; бэкап прежней версии с
  уникальным именем (`v-<время>[-n].html`, существующие бэкапы не перезаписываются), атомарная запись.
- Внешнее изменение: при чистом черновике - перечитать и перезагрузить превью; при грязном - баннер конфликта:
  «Взять версию с диска» (мои правки отменяются, но остаются в undo) или «Сохранить поверх» (с бэкапом версии диска).
- Время кадра, выбранная сцена и объект сохраняются при перезагрузке превью и после сохранения.

**Критерии:** тесты `source.test.ts` (сохранение байтов вне патча, комментарии/скрипты, вложенная разметка,
пути после вставки/удаления, нестандартный HTML), `history.test.ts`; ручная проверка выбора кликом.

## 3. Safe zone

- Две рамки поверх кадра: **текст** x 65-1015, y 250-1670 и **компоненты** x 65-1015 (по вертикали без ограничений).
- Исключения: аватары `.ava`, концовка движка, `.wall-bg`, `.p5-deco`, `[data-safe="ignore"]`, `.bg` (фон и декор).
- Проверка (`src/editor/safety.ts` - чистая геометрия, сбор прямоугольников - `bridge.ts`):
  текущий кадр, сцена или весь ролик с шагом 0.5/0.2/0.1 с или «каждый кадр» плюс ключевые моменты (конец перехода,
  конец ключа камеры, `data-in + d`, конец `data-exit`) и момент за 1/60 с до конца сцены. «Каждый кадр» - шаг 1/30 с от
  `data-s` каждой сцены (`scanTimes`), а не сетка рендера f/30: кадры совпадают, только если `data-s` кратно 1/30.
  Кадры перехода по умолчанию пропускаются (флажок включает), концовка не проверяется; меряется DOM превью Studio, а не
  готовый mp4. Отчет показывает число и шаг проверенных кадров; ни один режим не гарантирует все кадры ролика.
- Камера учитывается: меряются прямоугольники после `render(t)`, т.е. с трансформацией сцены.
- Нарушения с объектом и временем, клик - перейти к кадру и выбрать объект.
- Пересечения - «потенциальные»: текст внутри карточки (предок) не считается; текст поверх/под чужим компонентом или
  другим текстом - предупреждение, вид «перекрыт» если компонент позже в DOM или выше по z-index.
- Исправление «Вместить»: расчет сдвига/ширины, пунктирная рамка предпросмотра, применение отдельной кнопкой (undo доступен).
  Выравнивание абсолютного объекта по краям и центру зоны.

**Критерии:** `safety.test.ts` (зоны, исключения, предок-карточка, пересечения, расчет «вместить»).

## 4. Каталог компонентов

- `src/editor/catalog.ts`: заголовок, текст, число с подписью, карточка-результат, сравнение, код, таблица, схема,
  изображение, аватар, формула. У каждого - описание, варианты и поля; HTML строится из классов `p5-world.css`
  (`.h/.h2/.h3`, `.p`, `.num`, `.card`, `.glass`, `.code5`, `.pic`, `.ava`, `.chip`). Время входа - текущее время или слово.
- Превью карточки каталога - iframe с настоящими стилями движка (без runtime).
- Формула: `<div class="tex"><!--tex ...--><!--/tex--></div>`; SVG делает существующий `engine/pipeline/tex2svg.mjs`
  (`POST /api/tex` обрабатывает копию черновика во временной папке вне проекта). HTML-имитации формул нет.
- Пользовательские пресеты: выбранный объект сохраняется в `video/N/work/studio-presets.json` (только этот ролик).

## 5. Камера

- `src/editor/camera.ts`: разбор и запись `data-camk` без потерь (`время цель масштаб [длительность] [кривая]`).
- Ключи на таймлайне, поля время/цель/масштаб/длительность/кривая, `data-camdim` сцены, выбор цели кликом
  (объекту без `id` добавляется уникальный `id`), привязка времени к слову из `words.json`.
- Пресеты: общий-деталь-результат, перевод между объектами, отъезд.
- Предупреждения: масштаб вне 1.08-1.2, длительность вне 0.5-1.4 с, старт во время перехода, цель шире 800px,
  нет цели. Ограничение масштаба safe zone остается в движке.

## 6. Движение объектов

- Вход: `data-in`, `data-a` (в p5w: `rise`, `left`, `right`, `drop`, `stamp`, `up`), `data-d`, `data-ease` (`glide`, `cine`, `soft`).
- **Новый уход** `data-exit="t[,d]"` (движок, `preset-dynamic.js`): прозрачность и сдвиг вверх 24px по smootherstep,
  без scale; свойство `translate`, не совмещать с `data-float`/`data-shake`. Все от `t`.
- Привязка к словам, цикл диапазона, скорость 0.25x/0.5x/1x, покадровый шаг.
- Проверка детерминизма: состояние после последовательного проигрывания к T сравнивается с прямым `render(T)`.

## 7. Переходы

- Галерея текущих (`down`, `up`, `dots`, `radial`, `grow`, `shrink`, `meme`) и новых:
  `dissolve` - плавное растворение (0.8 с, лучше для одного фона), `defocus` - расфокусировка (1 с, старая сцена
  уходит в размытие, новая проявляется из размытия). Без scale.
- Предпросмотр стыка (цикл от `a-0.6` до `a+d+0.6`), длительность показывается, предупреждение о повторе
  больше 2 подряд (с учетом автоматического выбора движка) и о `meme` без картинки.
- Совпадающие объекты между сценами (match move) **не реализуются**: нет надежного контракта связи объектов.
- Проверка - `engine/examples/transitions-new.html` и `engine/checks/transition-endpoints.mjs`.

## 8. Диагностика и история

- Список проблем: safe zone, текст (`ё`, длинные тире, положительный трекинг в `style`), переходы, фоны подряд,
  соседние палитры, камера, `p5gaps`, `data-sfx`, отсутствие концовки, `<base>`.
- До/после: превью сохраненной версии и черновика переключается.
- Бэкапы `work/studio-backups/` не удаляются и не перезаписываются.

## Страница «Музыка»

- Корень - `STUDIO_MUSIC_ROOT` (по умолчанию `/Users/samgold/Desktop/музыка`), только чтение.
- `GET /api/music` - рекурсивный каталог поддерживаемых аудио (MP3/WAV/M4A/FLAC/OGG, регистр не важен),
  число пропущенных файлов, ошибка недоступной папки. `GET /api/music/file?path=` - файл с Range.
  Путь только относительный, без `..`, realpath внутри корня (symlink наружу отклоняется).
- `POST /api/videos/:id/music` - копирует один выбранный файл в `video/N/music/` (без перезаписи; одинаковый файл
  переиспользуется) и сохраняет `music` в `video.json` существующим `setAudio` с проверкой `base` и бэкапом.
  Вся операция (проверка base, копия, запись) идет в очереди ролика вместе с `PUT /audio` (`authoring.withAudio`),
  поэтому параллельный импорт не переиспользует еще не записанный файл. Если сохранение настроек не удалось, удаляется
  только файл, созданный этим вызовом.
- Фильтр папок: «Все папки» и «(корень)» - разные значения (`src/music-filter.ts`).
